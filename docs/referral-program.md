# Реферальная программа (пакет `federation`)

Этот пакет нужен, если вы строите программу «приведи друга»: ваш участник
получает ссылку, делится ею, и когда приведённый человек оставляет заявку или
покупает, участнику (а при многоуровневой схеме и тем, кто привёл его самого)
начисляется вознаграждение. Recca ведёт цепочку «кто кого привёл» и считает
деньги.

Если вам нужна **партнёрская сеть** (блогеры, рекламодатели, офферы, выплаты),
вам нужен другой пакет, `cpa`: [README](../README.md). Пакеты независимы,
и ключи у них разные.

```sh
go get go.recca.ru/sdk/federation
```

Словарь общий с [README](../README.md#словарь-что-означают-слова), плюс несколько
слов этого пакета:

| Слово | Что это |
|---|---|
| **Участник** | Ваш человек, который приводит других. Recca знает его по контактам и выдаёт вам его `TenantReccaID` |
| **`TenantReccaID`** | Идентификатор участника **в вашей сети**. Хранится у вас; им вызываются все методы «про этого человека». У другой сети на того же человека будет другой идентификатор |
| **Реферальная ссылка** | Ссылка участника на оффер. Содержит подписанную метку `recca_ref` |
| **`recca_ref`** | Подписанная метка из адреса вашей страницы. По ней Recca узнаёт, кто привёл. Вы её не придумываете, а передаёте как пришла |
| **Заявка (лид)** | Приведённый человек оставил заявку: «кто привёл» зафиксировано |
| **Конверсия** | Событие, за которое платят: покупка, регистрация. Recca начисляет вознаграждение |
| **Каскад, колена** | Цепочка приведших: тот, кто привёл покупателя, тот, кто привёл его, и дальше. Деньги делятся по ней по правилам сети |

⚠ Ключ (`X-Recca-Tenant-Key`) живёт только на вашем сервере, как и в
партнёрской сети. Ключи `federation` и `cpa` разные.

⚠ **Отличие от партнёрской сети:** здесь участника сводят по его контактам
(почта, телефон, соцсети), потому что «приведи друга» работает с живыми
людьми. В партнёрской сети (`cpa`) личные данные, наоборот, не принимаются
вовсе.

## Шаг 1. Подключиться

```go
package main

import (
	"context"
	"fmt"
	"log"
	"os"

	"go.recca.ru/sdk/federation"
)

func main() {
	ctx := context.Background()

	c, err := federation.New(os.Getenv("RECCA_TENANT_KEY"), &federation.ClientOptions{
		Environment: federation.Sandbox, // песочница; пустое значение означает бой
	})
	if err != nil {
		log.Fatal(err)
	}

	self, _, err := c.Self.Get(ctx)
	if err != nil {
		log.Fatalf("нет связи: %v", err)
	}
	fmt.Println("среда:", self.Environment) // ждём sandbox
}
```

⚠ Пустое `Environment` означает **бой**, как и в `cpa`. Пока пробуете, пишите
`federation.Sandbox` и проверяйте строку `среда: sandbox`.

## Шаг 2. Завести участника

```go
user, _, err := c.Users.Upsert(ctx, federation.UpsertUserInput{
	Email:         "petr@example.ru",
	FirstName:     "Пётр",
	EmailVerified: true,
})
if err != nil {
	log.Fatal(err)
}
fmt.Println(user.TenantReccaID, user.IsNew, user.ClaimRequired)
```

- Вызов **идемпотентен по контактам**: второй раз с той же почтой вернёт того же
  человека и `IsNew == false`. Повторять его безопасно.
- Сохраните `TenantReccaID`: им зовутся все следующие методы.
- `ClaimRequired == true` значит, что человек уже есть в Recca сам по себе:
  сеть его нашла, но распоряжаться им не может, пока он не передаст ей
  доступ.

## Шаг 3. Выдать участнику ссылку

```go
link, _, err := c.ReferralLinks.Create(ctx, user.TenantReccaID, federation.CreateReferralLinkInput{
	OfferID: "off_1",
})
if err != nil {
	log.Fatal(err)
}
fmt.Println(link.ShortURL, "переиспользована:", link.Reused)
```

Ссылка для пары «участник и оффер» одна: повторный вызов вернёт ту же
(`Reused == true`).

Когда приведённый человек переходит по ссылке, он попадает на вашу страницу, и
в адресе у неё стоит метка `recca_ref`. **Сохраните её как есть**: она
понадобится на следующих шагах.

## Шаг 4. Засчитать заявку

Приведённый оставил заявку на вашем сайте. Сообщите об этом, передав метку из
адреса:

```go
lead, _, err := c.Leads.Create(ctx, federation.CreateLeadInput{
	ReccaRef:   "метка_из_адреса_страницы",
	ExternalID: "form-2026-000451", // номер отправки формы в вашей системе
	LeadSource: "form_submit",
})
if err != nil {
	log.Fatal(err)
}
```

⚠ **`ExternalID` — это номер события, а не попытки.** Защита от дублей
держится именно на нём. Если сгенерировать его заново при повторе после сбоя,
защита выключится: появятся две заявки, и вознаграждение начислят дважды. Здесь
не используется заголовок `Idempotency-Key`: сервер его не читает, поэтому
клиент его и не шлёт.

## Шаг 5. Засчитать покупку

Когда приведённый купил, зафиксируйте результат. Recca начислит
вознаграждение приведшему и по цепочке выше:

```go
conv, _, err := c.Conversions.Register(ctx, federation.RegisterConversionInput{
	EventType:  "purchase",
	ExternalID: "order-0751", // номер заказа в вашей системе
	AmountRub:  2500,
	ReccaRef:   "метка_из_адреса_страницы",
})
if err != nil {
	log.Fatal(err)
}
```

- Повтор с тем же `ExternalID` вернёт `200` и **не заплатит второй раз**.
- Префикс `recca:` в номере занят платформой: такой номер отбивается кодом
  `RESERVED_EXTERNAL_ID`.

## Шаг 6. Отменить покупку

```go
res, _, err := c.Conversions.Reverse(ctx, "order-0751", federation.ReverseConversionInput{
	Reason: "возврат заказа", // обязательно: отмена денег без причины никем не разбирается
})
if err != nil {
	log.Fatal(err)
}
if !res.FullyReversed() {
	// Часть вознаграждений уже выплачена, отменить её нельзя.
	// Список лежит в res.UnreversedLegs, у каждого пункта своя причина.
}
```

⚠ Ответ `200` приходит и при **частичной** отмене. Читайте
`res.FullyReversed()`, а не код ответа. Если вы делаете несколько частичных
отмен одной покупки, каждая должна нести свой `ReversalID`: без него обе
считаются одной операцией, и вторая вернёт результат первой.

Право на отмену отдельное от права засчитывать результат: ключ, которым вы
принимаете покупки, не обязан уметь забирать деньги обратно.

## Шаг 7. Показать участнику баланс

```go
balance, _, err := c.Promos.Balance(ctx, user.TenantReccaID)
if err != nil {
	log.Fatal(err)
}
if rub, known := balance.Spendable(); known {
	fmt.Println("можно потратить сейчас:", rub)
}
```

## Шаг 8. События

События (`lead.created`, `conversion.cascaded` и другие) приходят на ваш адрес
тем же механизмом, что и в партнёрской сети: пакет `webhook`. Приёмник и
главное правило (отбрасывать повторы по `event_id`) описаны в
[README, шаг 7](../README.md#шаг-7-получать-события).

## Подводные камни

Каждый пункт — отличие от того, чего ждёт интегратор.

**1. Защита от дублей — это `ExternalID` в теле, а не заголовок.** Сервер не
читает `Idempotency-Key` ни в одном методе. Повтор различается по `ExternalID`
(у заявки и конверсии) и по паре «участник и оффер» (у ссылки). Номер события
должен быть устойчивым.

**2. Поле `available` НЕ означает «доступно к выводу».** Оно значит «начислено
за всё время минус отменено», и вывод денег его не уменьшает. Сколько человек
может потратить сейчас, показывает `WalletCleared`. До первого вывода числа
совпадают, после — расходятся навсегда. В Go-типе они разведены именами
(`LifetimeNet` и `WalletCleared`) именно поэтому; в JSON имена прежние, потому
что сервер живой и поле читают другие клиенты.

⚠ `WalletCleared` — указатель, и `nil` значит «сервер не знает», а не «ноль»:
счёт человека может нести операции ещё какой-то сети, и разделить их нечем.
Спрашивайте `Balance.Spendable()`: вторым значением он говорит, знает ли
сервер.

**3. Дерево на разной глубине называет людей по-разному.** Первое колено
приходит идентификатором, которым можно звать API. Начиная со второго колена
это необратимый хеш: его можно только сравнить с другим хешем из того же
ответа. Тип узла это выражает: `node.Identity.Direct()` и `.Opaque()` возвращают
вторым значением ложь, если вид не тот.

**4. Отмена отвечает `200` и при частичной отмене.** Выплаченные
вознаграждения отменить нельзя: они приходят в `UnreversedLegs` с причиной у
каждого. Спрашивайте `res.FullyReversed()`.

**5. `Meta.Total` у разных списков означает разное.** У каталога офферов это
настоящее общее число. У списка заявок участника сервер считает `total` как
размер выданной страницы, поэтому строить по нему пагинацию нельзя; признак
конца — когда вернулось меньше, чем просили.

**6. `Badges.RequestPublic` ничего не меняет.** `Requested == true` значит «человеку
отправлено уведомление», а не «бейдж стал публичным»: видимость
двусторонняя, и действует та половина, что строже. `EffectiveVisibility` в
ответе остаётся прежней.

## Тестовый стенд и приёмка

`federationtest` — стенд на `httptest`. Он отвечает фикстурами и исполняет
ровно три правила идемпотентности (конверсия, заявка, ссылка). Поведение
платформы он не воспроизводит: это доказывает `Conformance` против живой
песочницы.

```go
func TestAcceptance(t *testing.T) {
	c, _ := federation.New(os.Getenv("RECCA_TENANT_KEY"),
		&federation.ClientOptions{Environment: federation.Sandbox})
	federationtest.Conformance(context.Background(), t, c,
		federationtest.ConformanceOptions{ExternalIDPrefix: "acme"})
}
```

⚠⚠ Набор первым делом спрашивает у самого сервера, песочница ли это
(`Self.Get`, поле `environment`), и **отказывается работать** на `production`,
`staging` и на пустом значении. Адрес клиента не доказывает ничего: его берут
из переменной окружения, а переменные путают. Набор, поверивший своей
настройке, создал бы заявки и конверсии на настоящих деньгах.

## Все методы

| Метод | Что делает | Право |
|---|---|---|
| `Self.Get` | Проверка связи и среда | нет |
| `Users.Upsert` | Завести участника или найти существующего | `users:upsert` |
| `Users.Get` | Профиль участника | `profile:read` (и `profile:email` для почты) |
| `Users.ListLeads` | Заявки, приведённые участником | `users:read` |
| `Users.Tree` | Дерево приведённых | `users:read` |
| `ReferralLinks.Create` | Ссылка участника на оффер | `users:impersonate` |
| `Offers.List` | Каталог офферов | `offers:read` |
| `Leads.Create` | Засчитать заявку | `leads:write` |
| `Conversions.Register` | Засчитать покупку и начислить вознаграждение | `conversions:write` |
| `Conversions.Reverse` | Отменить покупку полностью или частично | `conversions:reverse` |
| `Promos.Balance` | Баланс участника | `bonuses:read` |
| `Badges.RequestPublic` | Запросить публичный бейдж (уведомление человеку) | `badges:write` |
