# Recca Go SDK

Go-клиент для интеграции вашего сайта или сервиса с Recca: партнёрская сеть с
учётом переходов, заказов и выплат, а также реферальная программа. Этот
документ ведёт от «ничего нет» до работающей интеграции по шагам.

```sh
go get go.recca.ru/sdk@latest
```

Нужен Go 1.24 или новее.

| Пакет | Зачем он вам |
|---|---|
| `go.recca.ru/sdk/cpa` | **Партнёрская сеть (CPA).** Партнёры, офферы, ссылки, переходы, заказы, выплаты, статистика. Основной пакет, с него начинайте |
| `go.recca.ru/sdk/federation` | **Реферальная программа.** «Приведи друга»: участники, их ссылки, заявки, начисления. Отдельная тема, см. [docs/referral-program.md](docs/referral-program.md) |
| `go.recca.ru/sdk/webhook` | Принять событие, которое Recca шлёт на ваш сервер, и проверить подпись |
| `go.recca.ru/sdk/postback` | Подписать и проверить постбэк рекламодателя (если он шлёт заказы напрямую) |
| `go.recca.ru/sdk/cpatest` | Тестовый стенд без сети: проверить свой код и пройти приёмку |

## Как всё устроено

Recca ведёт **учёт денег** в партнёрской сети. Люди и сайты остаются вашими,
Recca считает, кому, сколько и когда заплатить.

```
 Рекламодатель ── платит за результат ──►  ┌──────────────┐
                                           │    Recca     │ ◄── ваш сервер (этот SDK)
 Партнёр (блогер) ── приводит людей ─────► │  учёт, холд, │
                                           │  выплаты     │ ──► события на ваш сервер
 Оператор сети ── настраивает в кабинете ► └──────────────┘
```

Путь одной продажи:

1. Оператор сети в кабинете Recca создаёт **оффер**: что продаём, сколько платим
   партнёру, какой срок проверки.
2. Ваш сервер заводит **партнёра** и получает для него **ссылку** на оффер.
3. Человек переходит по ссылке. Вы сообщаете Recca о **переходе**.
4. Человек покупает. Вы сообщаете о **заказе**. Recca считает деньги партнёру
   и на срок **холда** удерживает их: вдруг заказ вернут.
5. Холд прошёл, деньги стали **доступны к выплате**, Recca присылает событие.
6. Партнёр просит **выплату**. Оператор переводит деньги и отмечает это в
   кабинете.

Что **не** делается через SDK: заведение офферов, рекламодателей, ставок и
отметка «выплачено». Это работа оператора в кабинете Recca (`app.recca.ru`),
осознанно: правка условий меняет обещания, уже данные партнёрам, а деньги
подтверждает человек.

⚠ **Ключ доступа хранится только на вашем сервере.** Он открывает данные всех
ваших партнёров, а разграничивать людей (блогер A не должен видеть данные
блогера B) должен ваш сервер. В браузер и мобильное приложение ключ не
отдают никогда.

## Словарь: что означают слова

| Слово | Что это |
|---|---|
| **Сеть, оператор** | Ваша партнёрская сеть и человек, который её ведёт. Оператор работает в кабинете Recca, а ваш сервер через SDK |
| **Рекламодатель** | Тот, кто платит за результат: магазин, школа, банк. Его заказы вы приносите в Recca |
| **Партнёр, вебмастер, блогер** | Тот, кто приводит людей по своей ссылке и получает вознаграждение |
| **Оффер** | Предложение рекламодателя с условиями: «заказ курса — 500 ₽ партнёру». Заводит оператор |
| **Цель** | Результат, за который платят. У оффера бывает несколько: «заявка», «покупка» и т. д., у каждой своя ставка. Цель по умолчанию называется `1` |
| **Ссылка** | Постоянная ссылка партнёра на оффер |
| **Переход (клик)** | Человек перешёл по ссылке партнёра. У перехода есть идентификатор `click_id` |
| **Конверсия** | Результат, за который платят: заказ, заявка. Привязана к переходу |
| **Номер заказа (`external_id`)** | Идентификатор события **в вашей системе**: номер заказа, номер заявки. Общий для всей сети |
| **Холд** | Срок, в течение которого деньги за конверсию ждут: заказ могут вернуть. Длину задаёт оператор |
| **Выплата** | Заявка партнёра на вывод заработанного |
| **Постбэк** | Сообщение «заказ состоялся», которое присылает рекламодатель (или вы за него) |
| **Вебхук** | Обратное направление: событие, которое Recca шлёт на **ваш** адрес («холд прошёл», «возврат») |
| **Ключ арендатора** | Секретный ключ доступа вашей сети к SDK. Показывается один раз |
| **Песочница** | Отдельная копия Recca для проб: свои данные, письма никому не уходят, деньги не настоящие |
| **Бой (production)** | Настоящая Recca с настоящими деньгами |
| **Идемпотентность** | Свойство «одна и та же операция, посланная дважды, сработает один раз». Нужна, потому что сеть ненадёжна и запросы повторяются |
| **`request_id`** | Номер запроса, по которому Recca находит всю цепочку у себя. Приводите его, когда пишете в поддержку |

### Состояния конверсии

| Статус | Что значит |
|---|---|
| `pending` | Заказ принят «в работе», рекламодатель его ещё не подтвердил |
| `hold` | Подтверждён, деньги партнёра удерживаются на срок холда |
| `approved` | Холд прошёл, деньги доступны к выплате |
| `declined` | Отклонена или возвращена, деньги не начисляются либо отменены |
| `not_found` | Заказ пришёл, а перехода с таким `click_id` Recca не знает |

Когда вы присылаете заказ со статусом `approved`, он сразу попадает в `hold`,
а в `approved` переходит сам по истечении холда. Об этом приходит событие.

## Что понадобится до начала

1. **Go 1.24+**.
2. **Ключ арендатора для песочницы.** Его выдаёт Recca при подключении вашей
   сети: попросите у вашего менеджера. Ключ показывается один раз, сохраните
   его в менеджере паролей.
3. **Идентификаторы для проб из песочницы:** какой оффер брать и под каким
   партнёром работать (в песочнице заведены тестовые офферы для приёмки; их
   идентификаторы передают вместе с ключом).
4. **Публичный адрес на вашем сервере** для вебхуков, когда дойдёте до шага 7.

Ключ кладите в переменную окружения, а не в код:

```sh
export RECCA_CPA_KEY="<ваш ключ песочницы>"
```

## Шаг 1. Подключиться и проверить связь

```go
package main

import (
	"context"
	"fmt"
	"log"
	"os"

	"go.recca.ru/sdk/cpa"
)

func main() {
	ctx := context.Background()

	client, err := cpa.New(os.Getenv("RECCA_CPA_KEY"), &cpa.ClientOptions{
		Environment: cpa.Sandbox, // песочница; без этой строки клиент пойдёт в бой
	})
	if err != nil {
		log.Fatal(err)
	}

	self, _, err := client.Self.Get(ctx)
	if err != nil {
		log.Fatalf("нет связи: %v", err)
	}
	fmt.Println("среда:", self.Environment)               // sandbox
	fmt.Println("версия контракта:", self.ContractVersion)
	fmt.Println("запросов в минуту:", self.RateLimitPerMin)
}
```

⚠ **Пустое `Environment` означает БОЙ.** Пока пробуете, пишите
`cpa.Sandbox` явно и проверяйте строку `среда: sandbox` в выводе.

Запросов в минуту у вашего ключа ровно столько, сколько вернул `Self.Get`:
берите число оттуда, а не из документации. При превышении сервер отвечает
`429` и пишет, сколько ждать; клиент сам выдерживает паузу и повторяет.

**Что, если не работает:**

| Ошибка | Причина |
|---|---|
| `MISSING_TENANT_SCOPE` (401) | Ключ пустой, неверный или отозван. Проверьте переменную окружения |
| `INSUFFICIENT_SCOPE` (403) | У ключа нет права на этот метод. Напишите в Recca, какой метод нужен |
| `FEATURE_NOT_AVAILABLE` (403) | У сети не подключён продукт «CPA-сеть» |
| `PRODUCT_PAUSED` (403) | Продукт приостановлен, обычно из-за неоплаты |

## Шаг 2. Завести партнёра

Партнёр в Recca — это просто ваш идентификатор. **Имя, почту и телефон не
присылайте:** Recca их не принимает и откажет (`PII_NOT_ACCEPTED`). В
Recca живёт только непрозрачный `external_id`, суммы и факты. Кто за ним
стоит, знаете только вы.

```go
partner, resp, err := client.Partners.Upsert(ctx, cpa.UpsertPartnerParams{
	ExternalID: "blogger-42",       // ваш идентификатор: до 64 символов, A-Za-z0-9_.:-
	Role:       cpa.PartnerWebmaster,
})
if err != nil {
	log.Fatalf("партнёр не заведён: %v", err)
}
fmt.Println(partner.ExternalID, partner.Status, "новый:", resp.StatusCode == 201)
```

`Upsert` значит «завести или найти»: повторный вызов безопасен и вернёт
того же партнёра с кодом `200`. **И `201`, и `200` — успех.**

⚠ Роль и ставку агента на уже заведённом партнёре меняет только оператор.
Подробности и последствия для ночной синхронизации: [docs/pitfalls.md](docs/pitfalls.md).

## Шаг 3. Найти оффер и выдать ссылку

```go
offers, _, err := client.Offers.ListForPartner(ctx, cpa.ListOffersParams{})
if err != nil {
	log.Fatal(err)
}
for _, o := range offers {
	fmt.Println(o.ID, o.Name)
}

link, _, err := client.Links.Create(ctx, cpa.CreateLinkParams{
	PartnerExternalID: "blogger-42",
	OfferID:           offers[0].ID,
})
if err != nil {
	log.Fatal(err)
}
fmt.Println("ссылка партнёра:", link.TargetURL)
```

У оффера **две проекции**, и они разведены именами методов:

- `Offers.ListForPartner` и `Offers.GetForPartner` показывают то, что видит
  партнёр: его вознаграждение;
- `Offers.ListForAdvertiser` и `Offers.GetForAdvertiser` показывают то, что
  видит рекламодатель: его ставку. Оба метода требуют идентификатор
  рекламодателя аргументом.

Так сделано, чтобы партнёр не мог увидеть ставку рекламодателя и вычислить
маржу сети.

Выданная ссылка постоянная: повторный вызов с той же парой «партнёр и оффер»
вернёт ту же ссылку.

## Шаг 4. Засчитать переход

Когда человек перешёл по ссылке партнёра на вашем сайте, сообщите об этом:

```go
click, _, err := client.Clicks.Create(ctx, cpa.CreateClickParams{
	PartnerExternalID: "blogger-42",
	OfferID:           "off_1",
	ClientClickID:     "tap-7c1e", // ваш уникальный номер перехода
})
if err != nil {
	log.Fatal(err)
}

if click.Status == cpa.ClickTrafficback || click.ClickID == nil {
	// Это НЕ ошибка: запрос верный, но переход не принят: исчерпан лимит
	// оффера или гео не подходит. Идентификатора клика в этом случае нет.
	reason := "причина не названа"
	if click.Reason != nil {
		reason = *click.Reason
	}
	log.Printf("переход не засчитан: %s", reason)
	return
}
if click.RedirectURL != nil {
	fmt.Println("отправьте человека сюда:", *click.RedirectURL)
}
// Сохраните *click.ClickID: он понадобится, когда придёт заказ.
```

⚠ **Всегда присылайте `ClientClickID`.** Этот метод сам НЕ повторяется при
сбое сети, потому что повтор означал бы второй переход и лишний расход лимита
оффера. Свой номер перехода делает повтор безопасным: Recca вернёт тот же клик.

## Шаг 5. Сообщить о заказе

Когда человек купил, сообщите об этом, указав `click_id` перехода:

```go
conv, resp, err := client.Conversions.Create(ctx, cpa.CreateConversionParams{
	ClickID:    *click.ClickID,
	ExternalID: "order-0751",        // номер заказа в вашей системе
	Status:     "approved",
	SumRUB:     cpa.RUBPtr(2500),    // сумма заказа в рублях
})
switch {
case errors.Is(err, cpa.ErrWindowExpired):
	log.Print("с перехода прошло слишком много времени, заказ не засчитан")
	return
case errors.Is(err, cpa.ErrGoalDisabled):
	log.Print("цель выключена оператором: новые заказы по ней не принимаются")
	return
case err != nil:
	log.Fatalf("не принято: %v", err) // в тексте ошибки есть код и request_id
}
fmt.Printf("HTTP %d, статус %s, партнёру %s ₽\n", resp.StatusCode, conv.Status, conv.PayoutRUB)
```

Что нужно знать:

- **Номер заказа общий для всей сети.** Если у вас несколько рекламодателей
  с нумерацией «с единицы», добавляйте свой префикс: `shopA-1001`.
- **Повтор безопасен.** Тот же номер заказа с теми же данными вернёт ту же
  конверсию с кодом `200`. Если уже исполненный запрос повторили с другой суммой,
  будет ошибка `IDEMPOTENT_MISMATCH` (409), а не вторая выплата.
- **Статус `approved` сразу даёт `hold`.** Деньги партнёру начислены, но
  удерживаются на срок холда.
- Если у оффера несколько целей, называйте цель явно: `Goal: cpa.Ptr("sale")`.
  Без неё берётся цель по умолчанию `1`.
- Если заказ сначала приняли «в работе» (`pending`), а потом он подтвердился,
  вызовите `Create` с тем же номером и статусом `approved`: это переход, и
  итоговую сумму на нём можно передать.
- Приставка `recca:` в номере заказа занята платформой: так номер не примут.

## Шаг 6. Отменить заказ

Клиент вернул заказ? Отмените конверсию:

```go
conv, _, err := client.Conversions.Cancel(ctx, cpa.CancelConversionParams{
	ExternalID: "order-0751",
	Reason:     "возврат заказа",
})
if err != nil {
	log.Fatal(err)
}
fmt.Println(conv.ExternalID, conv.Status) // declined
```

Отмена **необратима**: отменённый заказ уже не подтвердить, для нового
заказа нужен новый номер. Повторная отмена безопасна и возвращает тот же
результат.

Если деньги по конверсии ещё не вышли из холда, они просто аннулируются. Если
уже выплачены, судьбу решает политика сети: возврат удерживается из будущих
начислений или списывается как убыток оператора.

## Шаг 7. Получать события

Холд проходит сам, без вашего запроса. Чтобы узнать об этом сразу, а не
опросом, укажите адрес на вашем сервере:

```go
hook, _, err := client.Self.SetWebhook(ctx, cpa.SetWebhookParams{
	URL: "https://example.ru/recca/events",
})
if err != nil {
	log.Fatal(err)
}
if hook.Secret != nil {
	// ⚠ Секрет показывается ОДИН раз. Сохраните его сразу.
	fmt.Println("секрет вебхука:", *hook.Secret)
}
```

Recca шлёт четыре события:

| Событие | Когда |
|---|---|
| `cpa.conversion.approved` | холд прошёл, деньги доступны к выплате |
| `cpa.conversion.declined` | конверсия отклонена рекламодателем или антифродом |
| `cpa.conversion.reversed` | прошёл возврат, начисление отменено |
| `cpa.payout.paid` | оператор отметил выплату оплаченной |

Приёмник события на вашем сервере:

```go
receiver := webhook.Receiver{
	Secret: os.Getenv("RECCA_WEBHOOK_SECRET"),
	Seen:   store, // память о виденных событиях, см. ниже
}

http.HandleFunc("/recca/events", func(w http.ResponseWriter, r *http.Request) {
	body, err := io.ReadAll(r.Body) // читайте СЫРОЕ тело, как пришло
	if err != nil {
		w.WriteHeader(http.StatusBadRequest)
		return
	}
	env, err := receiver.Accept(r.Context(), r.Header.Get(webhook.HeaderName), body)
	switch {
	case errors.Is(err, webhook.ErrDuplicate):
		w.WriteHeader(http.StatusOK) // это событие уже обработано: ответить 200 и ничего не делать
		return
	case err != nil:
		w.WriteHeader(http.StatusBadRequest) // подпись не сошлась или тело повреждено
		return
	}

	switch env.EventType {
	case "cpa.conversion.approved":
		var data map[string]any
		if err := env.UnmarshalData(&data); err == nil {
			log.Printf("конверсия подтверждена: %v", data["external_id"])
		}
	case "cpa.payout.paid":
		// отметить выплату у себя
	}
	w.WriteHeader(http.StatusOK)
})
```

⚠⚠ **Одно и то же событие может прийти дважды.** Если ваш `200` потерялся по
дороге, Recca пришлёт событие снова, и подпись у повтора **настоящая**. От
двойной обработки защищает только память о виденных событиях (`Seen`), которая
ищет повтор по `event_id`. Без неё начисление выполнится дважды при зелёной
проверке подписи.

`Seen` — это интерфейс с одним методом. В бою его делают уникальным индексом
по `event_id` в вашей базе. Готовый `webhook.NewMemorySeen` годится только для
проб: перезапуск стирает память, а второй экземпляр приложения её не видит.

⚠ Секрет вебхука при потере не восстановить: вызовите `SetWebhook` с
`RotateSecret: true`, прежний секрет перестанет действовать.

## Шаг 8. Баланс, выплаты, статистика

```go
balance, _, err := client.Partners.Balance(ctx, "blogger-42")
if err != nil {
	log.Fatal(err)
}
fmt.Println("доступно:", balance.AvailableRUB, "в холде:", balance.OnHoldRUB, "порог:", balance.MinPayoutRUB)

if balance.CanRequest { // порог и сумма уже учтены Recca, не считайте сами
	from, to := cpa.NewDate(2026, time.September, 1), cpa.NewDate(2026, time.September, 30)
	params, err := cpa.NewPayoutParams("blogger-42", balance.AvailableRUB, from, to)
	if err != nil {
		log.Fatal(err)
	}
	payout, _, err := client.Payouts.Create(ctx, params)
	if err != nil {
		log.Fatal(err)
	}
	fmt.Println("заявка:", payout.AmountRUB, payout.Status)
}

rows, _, err := client.Statistics.Get(ctx, cpa.StatisticsParams{GroupBy: cpa.StatisticsByOffer})
if err != nil {
	log.Fatal(err)
}
for _, row := range rows {
	fmt.Println(row.Key, row.Clicks, row.Conversions, row.PayoutRUB)
}
```

- **Порог выплаты** принадлежит сети и меняется оператором. Берите его из
  `Balance`, а не из своей константы.
- **Заявка на выплату** опознаётся парой «партнёр и период». Повтор за тот же
  период с той же суммой вернёт ту же заявку. С другой суммой: `409
  IDEMPOTENT_MISMATCH`, вторая заявка не создаётся.
- **«Выплачено»** ставит оператор в кабинете. После этого приходит событие
  `cpa.payout.paid`.
- В статистике день конверсии считается по времени заказа (`occurred_at`), а
  если вы его не присылали, по времени приёма.

## Шаг 9. Проверить свой код без сети

`cpatest` поднимает у вас в памяти тестовую копию Recca. Это быстрые тесты в
вашем CI без ключа и без сети.

```go
func TestMyIntegration(t *testing.T) {
	stand := cpatest.NewServer(t)
	client := stand.Client(t)

	_, _, err := client.Conversions.Create(context.Background(), cpa.CreateConversionParams{
		ClickID: "clk_1", ExternalID: "order-1", Status: "approved",
	})
	if err != nil {
		t.Fatal(err)
	}
	if got := len(stand.Requests()); got != 1 { // что именно ушло на сервер
		t.Fatalf("ушло %d запросов, ждали один", got)
	}

	// Проверить, как ваш код ведёт себя при отказе:
	stand.PrepareError(cpa.CodeGoalDisabled)
	_, _, err = client.Conversions.Create(context.Background(), cpa.CreateConversionParams{
		ClickID: "clk_1", ExternalID: "order-2", Status: "approved",
	})
	if !errors.Is(err, cpa.ErrGoalDisabled) {
		t.Fatalf("ждали ErrGoalDisabled, получили %v", err)
	}
}
```

**Что стенд доказывает:** что ваш код собирает правильные запросы, правильно
разбирает ответы и проходит ветки ошибок.

**Чего стенд НЕ доказывает:** поведение настоящей Recca. Числа в его ответах
выдуманные. Размер холда, ставки, лимиты, гео и права партнёра проверяйте
в песочнице (шаг 10).

Режимы заготовленного отказа:

| Вызов | Что делает | Когда |
|---|---|---|
| `PrepareError(код)` | отказ на ОДИН следующий запрос | клиент без повторов (`stand.Client(t)`) |
| `HoldError(код)`, потом `ClearError()` | отказ на КАЖДОМ запросе до снятия | ваш собственный клиент с повторами |

⚠ Одноразовый отказ на повторяемом коде (`500`, `503`, `429`) «съедает»
политика повторов клиента: первая попытка получает отказ, вторая проходит, и
тест зеленеет по неправильной причине. С клиентом с повторами берите
`HoldError`.

## Шаг 10. Пройти приёмку в песочнице

Когда код работает на стенде, проверьте его на настоящей песочнице. Набор
`cpatest.Conformance` сам пройдёт всю цепочку: партнёр, ссылка, переход,
заказ, повтор заказа, выплата, проверка подписей. Каждый шаг пишет
`request_id`, так что вывод `go test -v` и есть протокол приёмки.

```go
func TestAcceptance(t *testing.T) {
	client, err := cpa.New(os.Getenv("RECCA_CPA_SANDBOX_KEY"), &cpa.ClientOptions{Environment: cpa.Sandbox})
	if err != nil {
		t.Fatal(err)
	}
	cpatest.Conformance(t, client, cpatest.ConformanceOptions{})
}
```

```sh
RECCA_CPA_SANDBOX_KEY=<ключ песочницы> go test -run TestAcceptance -v
```

⚠⚠ **Набор работает только с песочницей.** До первого запроса он сверяет адрес
клиента и спрашивает у самого сервера, песочница ли это. На боевом ключе он
откажется и не пошлёт ни одного запроса. Это защита от того, чтобы ваш CI не
создавал партнёров и заявки на выплату в настоящей сети.

Что набор создаёт за прогон: партнёра (по умолчанию `conformance-webmaster`),
ссылку, переход, подтверждённый заказ на 2 500 ₽ и, если баланс позволяет,
заявку на выплату. Номера заказов уникальны на прогон.

Сценарии из договора (бренды и блогеры, целевое действие, revshare, несколько
конверсий с одного перехода) включаются опцией `Scenarios` и требуют от вас
идентификаторов тестовых офферов; Recca передаёт их вместе с ключом.
Полная таблица опций и переменных окружения: [docs/acceptance.md](docs/acceptance.md).

## Шаг 11. Выйти в бой

Перед переключением пройдитесь по списку:

- [ ] Приёмка в песочнице зелёная, протокол с `request_id` сохранён.
- [ ] **Боевой ключ** получен отдельно и лежит только на сервере (менеджер
      секретов), не в репозитории и не во фронтенде.
- [ ] В коде осталось **одно** место, где выбирается среда. Для боя уберите
      `Environment: cpa.Sandbox` (пустое значение означает бой) и проверьте
      в журнале запуска, что `Self.Get` вернул `environment: production`.
- [ ] Номера заказов (`external_id`) устойчивы: это номер **события**, а не
      попытки. Если сгенерировать его заново на повторе, защита от дублей
      выключится, а выглядеть всё будет нормально.
- [ ] Приёмник вебхуков отбрасывает повторы по `event_id` в **вашей базе**, а не
      в памяти процесса.
- [ ] Вы не присылаете имена, почты и телефоны партнёров и клиентов.
- [ ] Вы не считаете сами порог выплаты, срок холда и ставки: берёте их из
      ответов Recca.
- [ ] В журналах вашего приложения пишется `request_id` из ответа или ошибки.
- [ ] Бюджет запросов в минуту вам известен (`Self.Get`), и ваши фоновые
      задачи в него укладываются.

## Ошибки: что значат и что делать

Ветвитесь по **коду**, а не по тексту: текст сообщений меняется без
предупреждения.

```go
switch {
case errors.Is(err, cpa.ErrWindowExpired):
	// с перехода прошло слишком много времени
case errors.Is(err, cpa.ErrValidation):
	// клиент отказал сам, до сети: в тексте названо поле
case err != nil:
	log.Printf("ошибка: %v", err) // в тексте есть код и request_id
}
```

Сообщая в поддержку о проблеме, приложите `request_id` из ошибки или ответа.

| Код | HTTP | Что значит | Что делать |
|---|---|---|---|
| `INVALID_INPUT` | 400 | В запросе неверное поле: формат, длина, пустое значение | Читайте поле, названное в сообщении, и исправьте. Повтор бессмыслен |
| `PII_NOT_ACCEPTED` | 400 | Вы прислали похожее на имя, почту или телефон | Присылайте непрозрачный идентификатор вместо данных человека |
| `RESERVED_EXTERNAL_ID` | 400 | Номер начинается с `recca:` | Смените префикс |
| `OCCURRED_AT_OUT_OF_WINDOW` | 400 | Время события глубже 90 дней | Такой заказ не принимается |
| `UNKNOWN_GOAL` | 400 | У оффера нет такой цели | Сверьте код цели с `Offers.GetForPartner` |
| `GOAL_DISABLED` | 409 | Цель выключена оператором, новые заказы по ней не принимаются | Попросите оператора включить цель или шлите другую. Уже принятые заказы это не затрагивает |
| `WINDOW_EXPIRED` | 409 | С перехода прошло больше, чем позволяет оффер | Не повторять: задним числом не засчитывается |
| `ALREADY_CONVERTED` | 409 | По этому переходу уже засчитан заказ на ту же цель | Норма для офферов «один заказ на переход». Если нужно несколько, оператор включает флаг на цели |
| `EXTERNAL_ID_CONFLICT` | 409 | Этот номер заказа уже занят в сети другим оффером | Добавьте к номеру свой префикс |
| `ILLEGAL_TRANSITION` | 409 | Так статус менять нельзя: например, подтвердить отменённое | Для нового заказа нужен новый номер |
| `IDEMPOTENT_MISMATCH` | 409 | Тот же заказ или заявка пришли с другой суммой | Другая сумма означает другую операцию: сформируйте новый номер или период |
| `PARTNER_NOT_ACTIVE` | 409 | Партнёр сейчас работать не может | Партнёра приостановил оператор или вы деактивировали его |
| `PARTNER_NOT_FOUND` | 404 | Нет партнёра с таким `external_id` | Заведите его (шаг 2) или проверьте опечатку |
| `OFFER_NOT_FOUND`, `CONVERSION_NOT_FOUND`, `PAYOUT_NOT_FOUND`, `ADVERTISER_NOT_FOUND` | 404 | Объекта с таким идентификатором в вашей сети нет | Проверьте идентификатор |
| `BELOW_MIN_PAYOUT` | 400 | Сумма заявки ниже порога выплаты | Порог в `Balance.MinPayoutRUB` |
| `INSUFFICIENT_BALANCE` | 409 | Доступных денег меньше суммы заявки | Дождитесь окончания холда |
| `RATE_LIMIT_EXCEEDED` | 429 | Превышен бюджет запросов в минуту | Повторяемые методы клиент перешлёт сам после паузы, которую назвал сервер. Если ошибка не уходит, уменьшите частоту запросов |
| `INTERNAL_ERROR` | 500 | Сбой на стороне Recca | Повторяемые методы клиент перешлёт сам. Если не проходит, сообщите `request_id` |

Коды доступа (`MISSING_TENANT_SCOPE`, `INSUFFICIENT_SCOPE`,
`FEATURE_NOT_AVAILABLE`, `PRODUCT_PAUSED`) разобраны в шаге 1.

## Частые вопросы

**Оба успеха: и `201`, и `200`?** Да. `201` значит «создано сейчас», `200`:
«уже было, вот оно». Если считать успехом только `201`, код сломается на
первом же повторе.

**Клиент сам повторяет запросы?** Читающие запросы всегда. Записывающие только
те, у которых есть защита от дубля. Два метода не повторяются: `Clicks.Create`
(повтор был бы вторым переходом, спасает ваш `ClientClickID`) и
`Self.SetWebhook` (повтор потерял бы секрет, который показывается один раз).

**Почему у некоторых полей ответа указатели?** Потому что сервер законно
присылает `null`: «неизвестно» и «ноль» разные вещи. Разыменовывайте указатель
только после проверки на `nil`.

**Как показать партнёру его деньги?** Через `Partners.Balance`: доступно к
выплате, в холде, выплачено и порог. Блогер A не должен видеть данные блогера B,
эту проверку делает ваш сервер до вызова SDK.

**Можно ли хранить в Recca имена партнёров?** Нет, и это сделано намеренно. Если
нужно показывать имена оператору, подставляйте их у себя по `external_id`.

**Как сменить таймаут, прокси, логи?** В `cpa.ClientOptions`: `HTTPClient`,
`MaxRetries`, `Logger` (метод, путь, статус и `request_id`; тела запросов не
пишутся никогда), `UserAgent`.

**Где посмотреть примеры на каждый метод?** Они исполняемые:
`go test -run Example ./...` и файл
[`cpa/example_services_test.go`](cpa/example_services_test.go). Готовая
программа: [`examples/quickstart`](examples/quickstart/main.go).

## Все методы

Восемнадцать операций контракта, двадцать методов (у оффера две проекции).
«Право» — разрешение, которое должно быть у вашего ключа; без него ответ
`403 INSUFFICIENT_SCOPE`.

| Метод | Что делает | Право |
|---|---|---|
| `Self.Get` | Проверка связи: среда, версия контракта, бюджет запросов | `cpa:self:read` |
| `Self.SetWebhook` | Адрес для событий; секрет показывается один раз | `cpa:self:write` |
| `Partners.Upsert` | Завести партнёра или найти существующего | `cpa:partners:write` |
| `Partners.List` / `Partners.Get` | Список и карточка партнёров | `cpa:partners:read` |
| `Partners.Balance` | Доступно, в холде, выплачено, порог | `cpa:partners:read` |
| `Offers.ListForPartner` / `GetForPartner` | Офферы глазами партнёра | `cpa:offers:read` |
| `Offers.ListForAdvertiser` / `GetForAdvertiser` | Офферы глазами рекламодателя | `cpa:offers:read` |
| `Offers.Creatives` | Баннеры и посадочные оффера | `cpa:offers:read` |
| `Links.Create` | Постоянная ссылка партнёра на оффер | `cpa:links:write` |
| `Clicks.Create` | Засчитать переход (не повторяется сам) | `cpa:clicks:write` |
| `Conversions.Create` | Принять заказ или сменить его статус | `cpa:conversions:write` |
| `Conversions.List` / `Conversions.Get` | Список и карточка конверсий | `cpa:conversions:read` |
| `Conversions.Cancel` | Отменить конверсию | `cpa:conversions:reverse` |
| `Payouts.Create` / `Payouts.List` | Заявка на выплату и история заявок | `cpa:payouts:write` / `read` |
| `Statistics.Get` | Отчёт по офферам, партнёрам или дням | `cpa:stats:read` |

Для запроса, которого нет среди методов, есть `client.Do`: тот же разбор
ответов, ошибок и повторов.
