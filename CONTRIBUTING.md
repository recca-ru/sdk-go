# Для разработчиков SDK

Этот документ нужен тем, кто правит сам SDK. Если вы пользуетесь им для
интеграции, вам нужен [README](README.md).

Источник правды по поведению сервера — контракт в репозитории Recca:
`docs/federation/cpa-api.md` и `docs/federation/openapi-cpa.yaml`. Там, где
описание расходится с кодом сервера, верен код сервера
(`apps/backend/src/api/federation/v1/cpa/**`).

## Как устроен модуль

Модуль один, `go.recca.ru/sdk`, и одна версия на оба клиента (`cpa` и
`federation`). Транспорт (повторы, паузы, разбор конверта, потолок тела)
общий и лежит в `internal/`, то есть виден только внутри модуля. Две отдельные
модули означали бы вторую копию транспорта, а клиент `federation` внутри модуля
с именем `cpa` значил бы, что импорт врёт о предмете. Плата за единый модуль:
ломающая правка в одном клиенте поднимает версию и другого. Пока версия ниже
1.0, это ничего не стоит.

Старый путь `go.recca.ru/cpa` остаётся живым: кто вендорил `v0.1.0`, не ломается
и переезжает когда захочет.

| Пакет | Что в нём |
|---|---|
| `go.recca.ru/sdk/cpa` | клиент CPA, опции, ошибки, короткие имена типов: один импорт для быстрого старта |
| `go.recca.ru/sdk/cpatypes` | типы контракта CPA: деньги, идентификаторы, параметры, коды ошибок |
| `go.recca.ru/sdk/cpatest` | стенд и приёмочный набор `Conformance` для CPA |
| `go.recca.ru/sdk/federation`, `federationtypes`, `federationtest` | то же для реферальной программы |
| `go.recca.ru/sdk/reccatypes` | то, что у всех клиентов одно: конверт, машинерия ошибок, деньги, дата, страница |
| `go.recca.ru/sdk/postback` | подпись и проверка ВХОДЯЩЕГО постбэка рекламодателя |
| `go.recca.ru/sdk/webhook` | проверка подписи ИСХОДЯЩЕГО вебхука Recca |
| `go.recca.ru/sdk/internal/transport` | повторы, паузы, разбор конверта, отладка |

`reccatypes` не «общая свалка»: туда попадает только то, что у обоих клиентов
одно по коду платформы: конверт, коды общей рамы (`MISSING_TENANT_SCOPE`,
`INSUFFICIENT_SCOPE`, `RATE_LIMIT_EXCEEDED`, `INTERNAL_ERROR`, `INVALID_INPUT`),
`RUB`, `Date`, страница списка. Предметные коды остаются у своего клиента:
`PARTNER_NOT_FOUND` знает только CPA, а общий словарь заставил бы каждый клиент
обещать чужие отказы.

Два клиента пишут признак следующей страницы **по-разному**: CPA — `has_more`,
остальная федерация — `hasMore`. Расхождение живое и старше этого SDK;
`reccatypes.Meta` принимает обе формы, иначе на половине ответов поле молча
оставалось бы `nil`, и «страниц больше нет» было бы неотличимо от «сервер не
сказал».

`meta.request_id` обещает контракт CPA, а не вся платформа. Остальные методы
федерации его не шлют, а на их отказах блока `meta` нет. Идентификатор при этом
есть всегда: заголовком `X-Request-Id`. Читайте его из `Response.RequestID`,
который берёт заголовок и падает на `meta` только если заголовка нет.

Рантайм и типы пишутся **руками**, а не генерируются. Когда появится
генератор, швом станет граница пакета `cpatypes`: там живут типы контракта и
ничего кроме них. Клиент, транспорт и политика повторов останутся ручными:
там принимаются решения, а не повторяется форма.

## Проверка

Версия Go в `go.mod` — **1.24**, версия потребителя. Директива ограничивает
язык, но не символы стандартной библиотеки: вызов функции из более новой версии
соберётся у вас и упадёт у потребителя. Поэтому `go vet` обязателен, а
окончательное доказательство — сборка настоящим тулчейном 1.24
(`GOTOOLCHAIN=go1.24.13`).

```sh
gofmt -l .                          # должно быть пусто
go build ./... && go vet ./... && go test ./...
```

## Мутационный прогон

```sh
go run ./tools/mutate               # или с -run <подстрока имени>
```

Каждая мутация снимает одно решение и обязана уронить тест, который это
решение стережёт; красное по сборке не засчитывается. Каталог мутаций —
`tools/mutate/catalog.go`, его якоря сверяет обычный `go test`.

Мутация — это правка исходника, поэтому раннер:

- **не стартует на грязном дереве:** печатает `git status --porcelain` и выходит;
- восстанавливает файл после каждой мутации и по Ctrl-C / SIGTERM;
- перед мутацией пишет журнал в `.git/mutate-journal.json`, и если процесс убит
  жёстко, следующий запуск возвращает файл сам, но только если файл после
  обрыва никто не менял; иначе стоп, решает человек;
- после прогона проверяет, что дерево снова чистое.

## Векторы подписей и коды ошибок

`testdata/` — копии артефактов контракта, порождённых живым кодом Recca:
подписи постбэка, подписи вебхука, реестры кодов ошибок. Обновляются командой
`pnpm sdk:sync-contract <путь к клону>` из репозитория Recca
(`scripts/sdk-go/sync-contract.mjs`), руками не правятся.

Расхождение с оригиналом красит тесты **здесь**, а не у клиента: ломающая
правка подписи обязана быть видна раньше, чем её увидит интегратор. Поэтому
новый код ошибки на сервере сначала красит тест `TestErrorRegistryMatchesContract`,
и в `cpatypes/errors.go` его заводят в трёх местах: константа, ошибка-значение
и запись в реестр.

## Выпуск версии

1. Поднять `SDK` в `internal/version/version.go` и описать изменения в
   `CHANGELOG.md`. Приставку `-dev` снимают до тега: тег ставят на дерево,
   которое называет себя своим номером.
2. Прогнать проверку выше.
3. Поставить тег `vX.Y.Z`. Версия Go необратима: откат возможен только
   директивой `retract` в `go.mod`.
